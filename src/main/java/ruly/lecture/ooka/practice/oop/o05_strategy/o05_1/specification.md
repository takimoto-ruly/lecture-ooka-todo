## ショッピングモールと決済戦略

### 【概要】
異なる属性を持つショップ（服屋、本屋）が共通の「買い物システム（継承）」を持ち、レジで支払う際に「現金」「クレジットカード」などの決済方法を自由に切り替えられる（Strategy）仕組みを作ります。

### 【仕様】
1. **決済方法のインターフェース（Strategy）**
   - **抽象メソッド**: 引数として金額（整数型 `int`）を受け取り、決済完了メッセージ（文字列型 `String`）を返す。
2. **具体的な決済クラス（Concrete Strategy）**
   - クラスA（現金）: 「[金額]円を現金で支払いました」を返す。
   - クラスB（カード）: 「[金額]円をカードで支払いました（手数料0円）」を返す。
3. **親クラス：ショップ（Superclass）**
   - **フィールド**: 店舗名（文字列）、現在設定されている決済方法（1のインターフェース型）。
   - **コンストラクタ**: 店舗名と初期の決済方法を受け取って初期化する。
   - **メソッド1**: 決済方法を途中で変更する（setter）。
   - **メソッド2**: 引数として金額（`int`）を受け取り、現在設定されている決済方法を実行して、その結果のメッセージをそのまま返す。
4. **子クラス：特定のショップ（Subclass / 多態性の検証用）**
   - クラスA（服屋）: 親を継承。独自のメソッド「試着する」を持つ（標準出力に「試着しました」と表示）。
   - クラスB（本屋）: 親を継承。独自のメソッド「試し読みする」を持つ（標準出力に「試し読みしました」と表示）。
